* Introduction
  The Web experience of Plottr involves more than porting the code
  from the Electron version to the web.  Both the user experience and
  the feature set of a desktop application necessarily differ from the
  website.  In this document I'll enumerate the work that needs to be
  completed for the website in terms of both its user experience and
  the functional requirements that remain to be implemented.

* Functional Requirements
  The website is, for the most part, a functioning version of the
  desktop app that's served from a web server.  The following is an
  exhaustive list of the feature set of Plottr, indicating which of
  the features are available on the desktop and web versions of the
  application at the time of writing this document.

*** Permissions and Authorisation
    Three permission states exist in the application:
     - "owner",
     - "collaborator", and
     - "viewer".

    Permissions are enforced by a set of Firebase rules.

    Only owners can change "file" records for files.  This data
    includes the file name and meta data.

    Planned but not yet implemented: Only "owners" can add
    collaboration records for other users.

    Collaborators and owners can change any of the other data.  This
    includes values at the keys:
     - ~beats/~
     - ~books/~
     - ~cards/~
     - ~categories/~
     - ~characters/~
     - ~customAttributes/~
     - ~featureFlags/~
     - ~hierarchyLevels/~
     - ~images/~
     - ~lines/~
     - ~notes/~
     - ~places/~
     - ~series/~
     - ~tags/~
     - ~tour/~
     - ~ui/~
